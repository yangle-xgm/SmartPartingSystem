## 一、调用链路验证（已确认通畅）

```
浏览器 → Vite dev (localhost:3000) → proxy '/api' → 网关 (localhost:8080)
      → StripPrefix=0 原样转发 → 微服务 Controller (/api/xxx/yyy) → Result JSON
```

| 环节 | 配置 | 状态 |
|------|------|------|
| 前端 baseURL | `utils/request.js` = `/api` | ✓ |
| Vite 代理 | `vite.config.js`：`/api` → `http://localhost:8080` | ✓ |
| 网关路由 | `StripPrefix=0`，`/api/**` 按服务前缀转发 | ✓ |
| 后端前缀 | 8 个 Controller 均 `@RequestMapping("/api/xxx")` | ✓ |
| 响应格式 | `Result{code,message,data,timestamp}`，前端拦截器校验 `code !== 200` | ✓ |
| 分页格式 | `PageResult{total,records,current,size}`，前端取 `res.data.records/total` | ✓ |

## 三、必须处理的问题

### 🔴 P1-1 支付记录列表路径不一致（已修复）
- 前端原调用：`GET /api/payment/record/list`
- 后端实际：`GET /api/payment/list`
- **已执行修复**：`src/api/payment.js` 第 3 行 `url` 改为 `/payment/list`。
- 附注：计划书 5.2.5 写的也是 `/record/list`，与后端实现不符，建议同步更新计划书文档。

### 🔴 P1-2 管理员登录可能失败（已修复·方案A）
- `SysUserServiceImpl.passwordEncode()` 是"模拟 BCrypt"：`"$2a$10$" + MD5(密码)`；
- 原 `mapper/data.sql` 中密码是**真实 BCrypt 哈希**，与后端算法不一致 → 登录必失败。
- **已执行修复**：`mapper/data.sql` 全部 5 个账号按后端算法重算哈希——
  - `admin` / `property_mgr`（密码 admin123）→ `$2a$10$0192023a7bbd73250516f069df18b500`
  - `zhangsan` / `lisi` / `wangwu`（密码 user123）→ `$2a$10$6ad14ba9986e3615423dfca256d04e3f`
- 若数据库已导入过旧数据，请执行（或重新执行 data.sql）：
  ```sql
  UPDATE sys_user SET password='$2a$10$0192023a7bbd73250516f069df18b500' WHERE username IN ('admin','property_mgr');
  UPDATE sys_user SET password='$2a$10$6ad14ba9986e3615423dfca256d04e3f' WHERE username IN ('zhangsan','lisi','wangwu');
  ```

## 四、建议优化（不影响功能，但影响联调体验）

1. **登录参数传递方式（脆弱）**：前端 `login()` 用 `params`（query string）传账号密码，后端 `LoginDTO` 无 `@RequestBody`——当前能跑通，但密码会进 URL（可能被日志记录）。建议：前端改 `data` + 后端加 `@RequestBody`。
2. **看板饼图硬编码**：`dashboard/index.vue` 饼图数据写死 `[10,5,2,1]`，未用后端数据；后端 `/stats/dashboard` 也未返回车位状态分布。若要让饼图真实，需后端 dashboard 增加 `spaceStatus` 字段。
3. **区域值口径**：DB 与前端用的是 `A区/B区/C区`，而计划书/Mock 用 `A栋/B栋`——**前端与 DB 一致，计划书需改**，否则答辩文档与演示对不上。
4. **生产部署**：dev 走 Vite 代理；生产需在 Nginx 加 `/api → gateway:8080` 反向代理（Gateway 已配置 CORS 允许跨域）。
