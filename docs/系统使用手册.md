## 一、系统概述

### 1.1 系统定位

面向住宅小区的**智慧停车管理平台**，解决传统人工登记、现金收费模式下"车位信息不透明、进出效率低、缴费不便、管理粗放、安全追溯难"等问题。

### 1.2 目标用户

| 角色 | 说明 |
|---|---|
| 业主 | 在线查看车位状态、预约车位、查询订单、在线缴费、邀请访客、意见反馈 |
| 物业管理员 | 车位管理、订单管理、缴费管理、设备管理、反馈回复、通知发布 |
| 超级管理员（平台方） | 物业全部能力 + 数据统计、操作审计、用户管理、多小区管理 |

### 1.3 核心能力一览

- 车位**实时地图**（真实停车场布局：分区、车道、入口出口、有机网格）
- 车位**预约**（时段管理、超时自动释放、并发防超卖）
- 车辆进出**闭环**（车牌识别 → 自动分配车位 → 计费 → 支付 → 出场）
- **动态计费**（工作日/周末差异化费率、免费时长、每日封顶）
- 支付与**真实退款**、每日对账、共享车位 **70/30 分润**
- 通知/反馈**双向交互**（公告发布 + 业主反馈闭环）
- **多小区**管理（超管管理多个小区停车场）
- **AI 智能客服**与车牌识别（豆包 API）
- **H5 移动端**（手机自动跳转）
- 全链路**操作审计**、统一错误码、Sentinel 限流

## 四、数据库初始化

### 4.1 执行顺序

在 Navicat / mysql 客户端中按顺序执行：

1. **`mapper/init.sql`** — 创建库表结构（DDL，含全部 16 张表与多小区扩展）
2. **`mapper/data.sql`** — 导入预置测试数据

### 4.2 覆盖内容

**init.sql（DDL）**：

- 基础表：sys_user、parking_space、vehicle、billing_rule、parking_order、payment_record、device、notification、audit_log、parking_stats
- 业务扩展表：visitor_invite（访客邀请码）、payment_reconciliation（支付对账）、reservation（车位预约）、share_income（共享分润）、feedback（意见反馈）
- **多小区扩展**：community 表、parking_space.community_id、sys_user.community_id

**data.sql（测试数据）**：

- 预置账号 5 个（超管/物业/3 名业主）
- 车位 47 个（A 区 17、B 区 17、C 区 13，状态混合分布）
- 车辆、计费规则（工作日/周末）、订单、支付、设备、通知、统计
- 小区 3 个：智慧星河花园（200 位）、滨江国际社区（150 位）、阳光100（100 位）

### 4.3 刷新数据注意事项

- init.sql 中建表使用 `DROP TABLE IF EXISTS`，会清空旧表
- 若只需重置业务数据，重跑 data.sql 前先清空相关表，避免主键重复报错（`Duplicate entry`）
- parking_space 表 id 无 AUTO_INCREMENT，插入需显式指定 id

## 七、功能使用指南（PC 端）

### 7.1 欢迎页与登录

- 访问 http://localhost:3000 进入欢迎页，点击"进入系统"跳转登录
- 输入账号密码登录；登录成功后按角色进入对应首页
- 业主注册入口：登录页可跳转注册（注册后默认为业主角色）

**常见登录问题**：
- 点击登录后回到欢迎页 → 说明 JWT 写入失败或路由守卫异常，重新登录或检查网关/user 服务
- 提示"无权限" → 该账号角色无权访问当前页面

### 7.2 首页 Dashboard

所有角色可见，展示：
- 车位利用率（空闲/占用/预约统计）
- 近期收入、车流趋势
- 快捷入口

> 若统计数据为空，检查 stats 服务是否启动、parking_stats 表是否有数据。

### 7.3 车位预约（业主）

1. 进入"车位预约"，默认显示**车位实时地图**（按 A/B/C 区分组，含车道、入口出口）
2. 地图色块：绿色=空闲（可点击预约）、蓝色=占用、橙色=已预约
3. 点击绿色车位 → 选择开始/结束时间 → 确认预约
4. 右侧"我的预约"查看记录，可取消未入场的预约

**规则**：单次预约最多 2 小时；超时未入场自动释放；车位状态实时刷新。

- 表格/地图两种视图切换
- 按区域、类型、状态筛选

## 九、核心业务规则说明

### 9.1 车位预约与超时释放

- 预约流程：选车位 → 选时段（≤2 小时）→ 原子占用（防并发超卖）→ 写预约记录
- **ReservationExpireTask**：每 5 分钟扫描，预约到期未入场的车位自动释放回空闲
- 取消预约：业主可取消未入场的预约，车位立即释放

### 9.2 入场 / 出场闭环

**入场**（设备识别车牌 → 自动分配车位 → 生成订单）：
1. 摄像头识别车牌（置信度 <80% 时转人工确认）
2. 系统查找空闲车位（原子锁防两车占一位）
3. 生成停车订单（进行中），车位状态变占用

**出场**：
1. 车辆出场，系统计算时长
2. 按计费规则结算金额
3. 业主支付后订单完成、车位释放
4. 通知业主

### 9.3 动态计费规则

| 规则 | 说明 |
|---|---|
| 免费时长 | 临时车 30 分钟 / 访客车 15 分钟 |
| 计费单位 | 30 分钟 / 60 分钟 |
| 工作日/周末 | 周末费率更高（如 2.5 → 3.0 元） |
| 每日封顶 | 工作日 50 元 / 周末 60 元 |
| 月租车 | 按每月价格计费（300 元/月等） |

### 9.4 支付超时扫描

**PaymentTimeoutTask**：每 5 分钟扫描支付状态为待支付且超时的支付记录，自动置为失败。

### 9.5 超时订单自动补偿

**OrderCompensationTask**：每 10 分钟扫描"进行中 > 24 小时"的订单，自动结算费用，避免订单长期挂起。

### 9.6 支付与退款

- 支付时校验：订单状态必须是进行中、金额必须等于后端计算值（防篡改）
- 支付成功后：更新订单支付状态、生成支付流水、发送通知
- **真实退款**：调用退款逻辑（非仅改状态），同步更新订单支付状态为已退款

### 9.7 共享车位分润

- 业主可将固定车位标记为"共享"（is_shared=1）
- 共享车位产生停车收入后，按 **业主 70% / 物业 30%** 分润
- 分润记录写入 share_income 表

### 9.8 访客邀请码

- 业主生成 6 位邀请码，设置有效期
- 访客凭码入场（道闸自动开闸）
- 邀请码状态：有效(0)、已使用(1)、已过期(2)、已作废(3)
- 访客出场费用挂业主账户

### 9.9 统一错误码

系统采用统一错误码体系，前端根据 code 细分提示（如车位不可用、预约冲突、无权限等），业务异常与系统异常分离。

## 十三、常见问题排查

### 13.1 服务启动失败：端口被占用

```
Web server failed to start. Port 8082 was already in use.
```

**解决**：结束占用端口的旧进程后重启：

```powershell
# 查看占用进程
netstat -ano | findstr :8082
# 结束进程（PID 替换为实际值）
taskkill /PID <PID> /F
```

### 13.2 parking 服务启动失败：Caffeine Cache Bean 缺失

```
Parameter 1 of constructor ... required a bean of type 'com.github.benmanes.caffeine.cache.Cache'
```

**解决**：确认项目依赖包含 Caffeine，且存在 Cache 配置类；重新编译后重启。

### 13.3 服务启动失败：DataSource 未配置

```
Failed to configure a DataSource: 'url' attribute is not specified
```

**解决**：检查该服务 application.yml 中 MySQL 连接配置（host/port/账号/密码），确认 Nacos 配置已加载。

### 13.4 登录失败

- 检查网关（:8080）与 user 服务（:8081）是否启动、Nacos 注册正常
- 密码使用 BCrypt 加密，与 data.sql 预置哈希一致
- 登录接口：POST /api/user/login（body 传参，勿用 query 明文拼密码）

### 13.5 前端数据获取失败 / 404

```
No static resource api/parking/stats.
```

**解决**：该错误说明请求未命中 Controller，检查：
1. 对应后端服务是否已启动
2. 网关路由配置（/api/** → lb://smart-parking-xxx）
3. 前端 API baseURL 是否指向网关 :8080

### 13.6 车位地图数据不显示 / 状态不更新

- 车位地图接口需返回全部车位（含占用/预约），已修复
- Redis 缓存 30 秒过期，状态变更后自动失效本地 L1 缓存
- 若仍异常，重启 parking 服务

### 13.7 通知发送失败

- notification 表外键：user_id 必须存在（广播用 userId=1 admin）
- 通知 createTime 需手动设置（MyBatis-Plus 自动填充不生效）
- 查询用 OR 条件（发给自己的 + 广播的）

### 13.8 数据库操作报错

- 重跑 data.sql 报 `Duplicate entry` → 先清空对应表再执行
- parking_space 插入报 `Field 'id' doesn't have a default value` → id 需显式指定（表无 AUTO_INCREMENT）

### 13.9 手机无法进入 H5

- 确认访问地址为局域网 IP:3000（非 localhost）
- 系统按 UA 自动跳转 /h5；也可手动访问 /h5/home
- 浏览器需允许非 HTTPS 环境下的本地访问
