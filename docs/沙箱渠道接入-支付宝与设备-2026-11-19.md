# 沙箱渠道接入：支付宝支付 + 设备厂商通道

> 日期：2026-11-19
> 范围：`smart-parking-payment`（支付宝沙箱）、`smart-parking-device`（道闸厂商通道沙箱化）
> 前置决策：`renew-monthly` **保留**（不改成线下收款登记单）；支付渠道、设备渠道**都走沙箱**。

---

## 一、结论先说

| 渠道 | 处理方式 | 落地形态 |
|---|---|---|
| 微信支付 | **保持模拟** | 微信支付没有面向个人的公开沙箱（需商户号 + 服务商资质），毕业设计无法真实联调。接口与状态机保留，`mock-enabled` 控制开关 |
| 支付宝 | **接真实沙箱** | 引入官方 `alipay-sdk-java`，走沙箱网关 `openapi-sandbox.dl.alipaydev.com`，支持收银台支付、主动查询、原路退款、异步通知验签 |
| 设备厂商 | **沙箱协议 + 虚拟道闸** | 新增 `device.vendor` 字段与 `GateAdapter` 抽象；内置 `sandbox`（JSON 指令 + ACK 回执）与 `mqtt-plain`（纯文本）两种通道，附虚拟道闸模拟器 |
| renew-monthly | 保留 | 仍受网关 `ADMIN_ONLY_PATTERNS` 保护（仅 role=1/2 可调），不新增前端入口 |

沙箱不是"假装"，是真的走渠道 OpenAPI：代码、报文、验签、回执全部与生产一致，只有网关地址和三把密钥不同。答辩时可以讲"同一套代码改 3 个配置项即可切生产"，这是沙箱接入的核心价值。

## 二、支付宝沙箱

### 2.1 为什么沙箱能做到"真"

支付宝沙箱与生产共用同一套 OpenAPI 与同一套 RSA2 签名规范：

| 项 | 沙箱 | 生产 |
|---|---|---|
| 网关 | `https://openapi-sandbox.dl.alipaydev.com/gateway.do` | `https://openapi.alipay.com/gateway.do` |
| APPID | 沙箱控制台顶部 16 位数字 | 正式应用 APPID |
| 密钥 | 沙箱自定义密钥 | 生产密钥 |
| 接口 | `alipay.trade.*` 完全相同 | 同 |

因此**切换生产 = 改 `gateway-url` + 换三把密钥**，代码零改动。

### 2.2 已实现的链路

```
创建支付流水  POST /api/payment/create
      ↓
收银台下单    POST /api/payment/alipay/cashier?payNo=&scene=pc|h5   → 返回自动提交表单 HTML
      ↓  （前端写入新窗口，浏览器跳到沙箱收银台）
用户在沙箱收银台付款（沙箱买家账号，真扣沙箱余额）
      ↓
到账确认  ① POST /api/payment/callback/alipay/notify  （渠道异步通知，需公网）
         ② POST /api/payment/alipay/query?payNo=      （主动查询，本地闭环）
      ↓
入账（金额一致性校验通过才置已支付）→ MQ 通知订单 → 共享车位分润
```

另外提供：

- `POST /api/payment/alipay/precreate?payNo=` → 当面付二维码串（想用扫码支付时用）
- `GET  /api/payment/channels` → 返回各渠道当前模式，前端据此决定走模拟还是收银台
- 退款：`POST /api/payment/internal/refund?payNo=` 在 `payType=2` 且沙箱开启时**先调渠道退款**，成功后才改本地状态

### 2.3 三个关键设计（都是踩过的坑）

**① 主动查询不是"演示旁路"**
异步通知要求 `notify_url` 公网可达，本机开发拿不到公网地址。主动查询 `alipay.trade.query` 是生产环境标准的掉单兜底手段，这里复用同一套逻辑：前端在跳收银台后每 1.5 秒查一次，最多 60 秒。所以本地演示能闭环，生产也同样健壮。

**② 金额一致性闸门（`PaymentRecordServiceImpl.assertAmountMatches`）**
渠道回传的 `total_amount` 必须与本地应付**数值相等**（`compareTo`，不是 `equals`，否则 `100` 与 `100.00` 会误判）。少收 = 改价攻击，多收 = 串单，一律拒绝入账并打 ERROR 日志留痕。单测 `AlipaySettleAmountGuardTest` 锁死 5 个用例，含"0 元回传 vs 应付 30 元"的免费放行漏洞回归。

**③ 沙箱开启后关掉模拟通道**
`smart-parking.alipay.enabled=true` 时，`POST /api/payment/alipay/pay`（点一下就成功）直接返回错误并提示走收银台。两条通道并存 = 留一个免费绕过口子，和报告 P0-2 的问题同类。

### 2.4 接入步骤（本项目当前账号）

**已确认的沙箱应用**（2026-11-19 抄录自控制台，APPID 不是密钥，可入库）：

| 项 | 值 |
|---|---|
| APPID | `9021000172614567` |
| 绑定商户账号 PID | `2088721120609082` |
| 网关 | `https://openapi-sandbox.dl.alipaydev.com/gateway.do`（与代码默认值一致，无需改） |
| 接口加签方式 | **系统默认密钥（公钥模式已启用）** |

> 注意：控制台选的是「**系统默认密钥**」，密钥对由支付宝生成、在页面上直接看。
> 因此 `secrets/alipay-sandbox/` 里那份自建密钥对**本次不用**（那是「自定义密钥」模式才需要上传的）。
> 在「公钥模式 已启用」这一行点右侧「查看」，可分别复制**应用私钥**与**支付宝公钥**——
> 二者是一对，把「应用公钥」误当「支付宝公钥」填进去的表现是恒 `invalid-signature`。

给 `smart-parking-payment` 的运行配置加四个环境变量，重启后 `GET /api/payment/channels` 返回
`{"mode":"alipay-sandbox","ready":true,...}` 即成功：

```bash
SP_ALIPAY_ENABLED=true
SP_ALIPAY_APP_ID=9021000172614567
SP_ALIPAY_PRIVATE_KEY=<控制台「查看」里的应用私钥，单行>
SP_ALIPAY_PUBLIC_KEY=<控制台「查看」里的支付宝公钥，单行>
```

控制台的「服务器 IP 白名单」红字提示对沙箱不生效（沙箱不配也能调），只有切生产网关前才必须配。
付款必须用控制台「沙箱账号」里的**买家账号**在沙箱版支付宝 App 登录，真实账号付不了沙箱订单。

### 2.5 前端改动

- H5 `Orders.vue`、Web `my-orders` / `order` 三处支付入口：
  `payType === 2` 且 `channels.alipaySandboxReady` 为真 → 走收银台跳转 + 轮询查询；否则回落到原模拟通道。
- 公共逻辑抽到两端各自的 `src/utils/alipaySandbox.js`（零新增前端依赖：不引二维码库，直接用官方 PC/H5 支付返回的自动提交表单）。

## 三、设备厂商通道沙箱化

### 3.1 设计：把"接哪家厂商"变成数据

原来代码里道闸指令是硬编码 `mqttClient.publish(topic, "OPEN")`，换厂商就得到处改。现在：

```
DeviceServiceImpl ──► GateAdapterFactory ──► GateAdapter（按 device.vendor 选）
                                              ├─ SandboxGateAdapter    vendor=sandbox     JSON 指令 + ACK 回执
                                              ├─ MqttPlainGateAdapter  vendor=mqtt-plain  纯文本 OPEN/CLOSE
                                              └─ 你要接的厂商            vendor=厂商码      实现 GateAdapter 即可
```

设备表新增 `vendor` 字段（`V4__device_vendor.sql`，默认 `sandbox`），管理端设备表单可直接选厂商通道。**接真实厂商时业务流程（进场自动开闸、出口放行、门岗人工放行、管理端手动开关）一行都不用改。**

### 3.2 沙箱协议报文

指令主题：`device/gate/{deviceNo}/control`（沿用种子数据）或 `device/gate/{deviceNo}/cmd`

```json
{
  "cmd": "OPEN",
  "deviceNo": "GATE-A-001",
  "seq": "dbd65414083d43df",
  "ts": 1795057990835,
  "source": "smart-parking",
  "reason": "管理端手动开闸",
  "sign": "94cd6d37d52b60b1e9f13bc87b6be9bf"
}
```

回执主题：`device/gate/{deviceNo}/ack`

```json
{"cmd":"OPEN","deviceNo":"GATE-A-001","seq":"dbd65414083d43df","result":"OK","ts":1795057990910,"sign":"..."}
```

`sign = MD5(cmd|deviceNo|seq|salt)`：真实厂商协议普遍要求指令签名，否则**任何人往 broker 发一条报文就能抬杆**。虚拟道闸会校验签名，签名不对拒绝执行（单测 `GateSandboxTest.signRoundTrip` 锁定篡改检测）。

### 3.3 虚拟道闸（`SandboxGateSimulator`）

没有硬件也能端到端验证"下发 → 执行 → 回执"：

- 订阅 `device/gate/+/control` 与 `device/gate/+/cmd`
- 校验签名 → 往 `/ack` 回执 → 唤醒服务端等待中的 `GateAckRegistry`
- 只做协议应答，**不写数据库、不改设备状态**（设备在线状态由心跳决定，让模拟器顺手改状态会掩盖真实离线场景）

关闭开关：`smart-parking.device.simulator.enabled=false`

### 3.4 ACK 超时策略（有意为之的"宽松默认"）

`smart-parking.device.strict-ack` 默认 **false**：指令已投递到 broker（QoS 1）就算受理，仅标记 `ackTimeout=true` 并 WARN。

理由：现实里大多数道闸不实现 ACK。如果默认严格，会因为"没回执"拒绝放行，把车堵在出口——这比偶发误放行的运营损失更大。验收想验证端到端回执时把它打开即可（单测 `strictAckFailsWithoutAck` 覆盖）。

### 3.5 顺带修掉的两个设备域老问题

| 问题 | 原因 | 修法 |
|---|---|---|
| 工作目录反复出现 `smart-parking-device-service-tcplocalhost18830/` 空目录 | Paho 默认 `MqttDefaultFilePersistence` 会落盘 | 改用 `MemoryPersistence`（cleanSession 场景本就不需要本地队列） |
| broker 重启后设备域永久失联 | 原实现只在启动时连一次 | `MqttTransport` 统一连接，开启 `automaticReconnect`，并在 `connectComplete(reconnect=true)` 里恢复订阅（cleanSession=true 时 broker 不会替你记住订阅） |

### 3.6 可观测：指令流水

`GET /api/device/gate/command-log?limit=20`（管理端），管理端「设备管理」页底部新增「道闸指令流水」卡片：时间、设备、指令、通道、是否回执、耗时、原始报文。

## 五、切换生产要改什么

**支付宝**：`smart-parking.alipay.gateway-url` 换成 `https://openapi.alipay.com/gateway.do`，APPID/密钥换生产的，`notify-url` 换成公网地址。代码不动。

**设备**：给真实道闸实现一个 `GateAdapter`：

```java
@Component
public class HikvisionGateAdapter implements GateAdapter {
    public String vendor() { return "hikvision"; }
    public GateResult open(Device d, String reason) { /* 厂商 SDK / HTTP / MQTT 私有协议 */ }
    public GateResult close(Device d) { /* ... */ }
}
```

然后把设备记录的 `vendor` 改成 `hikvision` 即可。`GateAdapterFactory` 自动路由，业务侧无需改动。

## 六、遗留说明

- **微信支付仍是模拟**：没有公开沙箱是客观限制，不是偷懒。若要真实联调需企业主体 + 微信支付商户号 + 服务商进件，超出毕业设计范围。
- **异步通知本机收不到**：`notify-url` 需要公网可达（内网穿透或云服务器）。本地用主动查询闭环，两套代码都已就绪；上线时把 `notify-url` 换成公网地址即可同时生效。
- **`smart-parking-device-service-tcplocalhost18830/` 目录**：当前仍被**旧的** device 进程持有（`.lck` 文件锁），重启 device 后新代码不再生成该目录，可直接删除。
- **`renew-monthly`**：按决策保留，未做改造；仍仅管理端可调。
