## 3. 缺陷清单

> 严重度定义：**P0** 核心数据操作静默失败/数据损坏；**P1** 功能不可用或敏感信息泄漏；**P2** 功能可用但结果错误/缺校验；**P3** 体验与一致性问题。

### DEF-01 【P0】雪花 ID 以 JSON number 下发，前端精度丢失导致"按 id 操作"全部失效

- **模块**：车位管理、车辆管理、访客邀请（凡雪花主键实体均受影响）
- **现象**：新增数据（id 为 19 位雪花号）后，详情报「车位不存在」、编辑提示成功但不生效、删除提示已删除但数据仍在、H5 作废核验码报「邀请码不存在」。
- **复现步骤**：
  1. 管理员登录 → 车位管理 → 新增车位，编号填 `ZZ-9036301` → 保存成功；
  2. 翻到最后一页找到该车位 → 点「详情」→ 抽屉展示数据，同时右上角弹出 **「车位不存在」**（`GET /api/parking/space/<错误id>` 返回 5201）；
  3. 点「编辑」把月租改成 321 → 保存 → 提示「车位已更新」→ 刷新页面 → 月租仍为 **¥100**；
  4. 点「删除」→ 确认 → 提示「已删除」→ 刷新页面 → 车位**依然存在**；
  5. H5 → 访客邀请 → 生成核验码 → 点「作废该核验码」→ 提示 **「邀请码不存在」**。
- **根因**：后端返回 `"id": 2115696681016836097`，浏览器 `JSON.parse` 得 `2115696681016836000`（超出 `Number.MAX_SAFE_INTEGER`）。前端 `row.id` 已是错值；后端删除/更新未校验影响行数，`removeById` 影响 0 行仍返回 `code:200`，于是形成"提示成功但没生效"的静默失败。种子数据 id 较小（如 1、4、7），所以 2026-09 的历史数据操作正常，**新数据才暴露**。
- **证据**：原始报文 `"id":2115696681016836097` → JS 解析 `2115696681016836000`；用精确 id 调 `DELETE /api/parking/space/2115696681016836097` 返回 200 且数据被删（总数 89→87）；用四舍五入 id 调同一接口同样 200 但数据不动。截图 `01-车位详情报车位不存在.png`、`02-编辑保存提示成功但未生效.png`。
- **修复建议**：
  1. 后端统一把 Long 主键序列化为字符串（Jackson 全局 `SimpleModule.addSerializer(Long.class, ToStringSerializer.instance)`，或实体主键加 `@JsonSerialize(using = ToStringSerializer.class)`）；
  2. 所有 `updateById/removeById` 校验返回值，0 行抛 `BizException(ErrorCode.XXX_NOT_FOUND)`，禁止 200 假成功；
  3. 前端可加 `json-bigint` 兜底；
  4. 回归范围：车位、设备、车辆、邀请、反馈、通知等所有雪花主键模块。

### DEF-02 【P1】约束类错误把 MyBatis 原始异常与 SQL 语句直接抛给用户

- **模块**：车位管理（同类问题存在于所有依赖唯一索引的写接口）
- **现象**：重复编号/非法数值时，前端 toast 显示 `### Error updating database. Cause: java.sql.SQLIntegrityConstraintViolationException ... ### SQL: INSERT INTO parking_space ...`，控制台另有未捕获 `pageerror`。
- **复现步骤**：
  1. 车位管理 → 新增车位 → 编号填已存在的 `A-001` → 保存；
  2. 观察右上角提示：完整 MyBatis 异常栈（含 `com.smartparking.parking.mapper.ParkingSpaceMapper`、表名、索引名 `uk_space_no`）。
- **补充证据（更严重）**：`POST /api/parking/space` 传 `monthPrice: -5`，HTTP 仍为 **200**，body `code:500`，`message` 内含 `### SQL: INSERT INTO parking_space ( id, space_no, area, floor, type, status, month_price, ... ) VALUES ( ?, ... )` 与 `MysqlDataTruncation: Out of range value for column 'month_price'`（766 字符）。
- **影响**：泄漏数据库结构（表/列/索引/包名）；用户无法理解错误；HTTP 200 掩盖 500，监控与告警失真。
- **根因**：`GlobalExceptionHandler` 未覆盖 `DuplicateKeyException` / `DataIntegrityViolationException`；全局异常处理把 `e.getMessage()` 原样返回；`views/parking/index.vue:411 handleSubmit` 只有 `try/finally` 没有 `catch`，异常逃逸为未捕获 Promise。
- **修复建议**：后端补 `DuplicateKeyException → 5204「车位编号已存在」`、`DataIntegrityViolationException → 5400「数据不合法」`，且 5xx 只返回 traceId，不回显 message/SQL；前端 `request.js` 对 5xx 统一「服务繁忙，请稍后再试」，只在控制台记录详细报文；`handleSubmit` 补 `catch` 并 `ElMessage.error`。

### DEF-03 【P1】并发 401 时双 Token 静默续期失效，用户被强制退出登录

- **模块**：全局请求层（`utils/request.js`）
- **现象**：accessToken 失效但 refreshToken 仍有效时，首页 5 个并发接口同时 401 → 刷新成功后**仍然跳转 `/login`**，并连弹 4 次「登录已过期，请重新登录」。
- **复现步骤**：
  1. 正常登录后，把 `localStorage.token` 改为 `bad.access.token`（`refreshToken` 保持有效）；
  2. 直接打开 `/dashboard`（该页并发请求 `/device/status/overview`、`/stats/dashboard`、`/parking/all`、`/user/info`、`/notify/list`）；
  3. 观察：`POST /api/user/refresh` 返回 200 且 token 已更新，但页面仍落到 `/login`，并出现 4 条「登录已过期」提示。
- **根因**：`request.js:98-114` 只用 `isRefreshing` 布尔量挡住"重复发起刷新"，但**没有把后续 401 请求挂起等待刷新结果**；第二个及之后的 401 直接落到 `handleBusinessError(401)` → 清 token + `router.push('/login')`。
- **修复建议**：改为 pending 队列（首次 401 时创建 refresh Promise，其余 401 `await` 同一 Promise 后重放原请求；只有刷新失败才统一登出）；`isRefreshing=false` 后清空队列；401 toast 做 1 秒节流，避免连弹。

### DEF-04 【P2】月租价格缺少非负校验：负数被静默丢弃或以数据库异常收场

- **模块**：车位管理 → 新增/编辑
- **现象**：`el-input` 允许输入 `-5`；从界面提交会"新增成功"但列表月租价格显示「—」（值被丢弃，用户误以为已保存）；直接调用接口则抛数据库 `Out of range value`。
- **复现步骤**：车位管理 → 新增车位 → 月租价格填 `-5` → 保存 → 提示「车位已新增」→ 列表该行月租价格显示「—」（截图 `03-负数月租被接受.png`）。
- **根因**：前端表单无 `monthPrice >= 0` 规则；后端 DTO 无 `@Min(0)`，DB 列为无符号小数，最终由数据库报错兜底。
- **修复建议**：前端 `rules: [{ type: 'number', min: 0, message: '月租价格不能为负' }]`；后端 DTO 加 `@DecimalMin("0.00")` 并启用 `@Validated`；与 DEF-02 的异常映射一并处理。

### DEF-05 【P2】操作审计的「耗时」「IP」两列恒为空

- **模块**：操作审计（`/audit`）
- **现象**：10/10 条日志的耗时与 IP 都显示「—」。
- **证据**：`GET /api/audit/list` 返回 `ip: null, costTime: null`；前端渲染「—」属正确降级。
- **影响**：审计无法定位来源 IP、无法做性能回溯，安全审计能力打折。
- **修复建议**：网关 `OperationLogAspect` 从 `HttpServletRequest` 取 `X-Forwarded-For`/`getRemoteAddr`，环绕计时写 `costTime`；落库前做脱敏与长度截断。

### DEF-06 【P2】业主首页「最近停车记录」状态标签错误（已取消显示为「待缴费」）

- **模块**：PC `/dashboard`（业主视角）
- **现象**：订单 `ORD202610281919533783`（`status=2 已取消`、`payStatus=0`）在首页显示 **「待缴费」**，而在「我的订单」显示「已取消」，两处口径矛盾；0 元已完成单同样会被标成「待缴费」。
- **复现步骤**：`zhangsan` 登录 → 首页 → 「最近停车记录」第 2 条 → 标签「待缴费」→ 点「全部订单」→ 同一订单显示「已取消」。
- **根因**：`views/dashboard/index.vue:198-199` 只判断 `status===0` 与 `payStatus===1`，遗漏 `status===2`（已取消）与 0 元单；`:442` 的 `myStats.pending` 也把 0 元单算进"待支付"。
- **修复建议**：把 `my-orders` 的 `isFree`/`effStatus` 抽到 `utils/order.js` 复用，首页与列表统一口径。

### DEF-07 【P2】数据看板「当前在场 0 辆」与车位实时分布「已占用 23」自相矛盾

- **模块**：PC `/dashboard`（管理端）
- **现象**：页面同时出现「当前在场 **0** 辆」与「已占用 **23**」，且「今日入场 0 车次」。
- **证据**：`/api/stats/dashboard` → `currentParked: 0`；`/api/parking/all` 87 个车位中 23 个 `status=1 已占用`。两套口径来自不同服务，未对齐。
- **影响**：运营看板核心指标失真，容易被据此做出错误判断。
- **修复建议**：`stats` 服务的 `currentParked` 改为取 parking 服务实时占用数（或 Redis 实时计数 + 每日快照对齐）；前端在数据源不一致时增加说明 tooltip。

### DEF-08 【P2】数据统计「平均利用率」恒为 0、趋势图只有 1 天数据

- **模块**：PC `/statistics`
- **现象**：「平均利用率 0.0%」「车位利用率趋势」仅一个点；「高峰时段」为「—」。而实际上当前占用率约 26%。
- **证据**：`GET /api/stats/occupancy?startDate=2026-10-01&endDate=2026-10-29` → `{"totalSpaces":[0],"dates":["2026-10-28"],"occupiedSpaces":[0],"avgOccupancy":0}`（截图 `04-统计利用率恒为0.png`）；`GET /api/stats/peak?date=2026-10-29` → `[]`。
- **根因**：统计任务未按日回填 `totalSpaces`，缺失日期直接丢点；`peak` 依赖当日入场事件，无事件时返回空数组，前端图表无空态。
- **修复建议**：按日补点（缺失日 `occupied=0, total=车位总数`）；`peak` 返回近 7 日兜底或前端显示「暂无数据」占位；见 DEF-11。

### DEF-09 【P3】登录失败提示被前端硬映射覆盖，无法区分"验证码错误"与"密码错误"

- **模块**：PC/H5 登录
- **现象**：验证码输错时提示「用户名或密码错误」。
- **证据**：`POST /api/user/login` 在「验证码错误」时实际返回 `{"code":5101,"message":"验证码错误或已过期"}`，但 `utils/request.js:25-43` 的 `CODE_MESSAGE[5101] = '用户名或密码错误'` 覆盖了后端 message。
- **影响**：用户排查方向错误（反复改密码）；也弱化了「验证码错误」的引导。
- **建议**：5101 不再硬覆盖（改用后端 message），或后端拆分为 5101 账号密码错误 / 5105 验证码错误。

### DEF-10 【P3】车辆搜索按脱敏串匹配，输入完整车牌搜不到

- **模块**：车辆管理（PC `/vehicle`）
- **现象**：搜索框提示「搜索车牌（脱敏匹配）」，输入 `湘A00001` 返回 0 条；输入列表里的 `湘A****7` 才能命中。
- **证据**：`views/vehicle/index.vue:203-211` 用 `plateNoMasked.includes(k)` 做客户端过滤。
- **建议**：placeholder 改为示例（如「搜索 湘A\*\*\*\*7」）；或后端提供按车牌密文精确查询的接口，前端改为服务端搜索。

### DEF-11 【P3】图表/列表空态缺失

- **模块**：数据统计 →「高峰时段分析」
- **现象**：`/stats/peak` 返回空数组时，图表区域只剩坐标轴，无「暂无数据」提示；「车位利用率趋势」同理。
- **建议**：ECharts 无数据时渲染统一的 `graphic` 空态文案，与表格空态风格一致。

### DEF-12 【P3】H5 未提供 favicon，控制台持续 404

- **现象**：H5 任意页面控制台报 `Failed to load resource: 404 (http://localhost:3001/favicon.ico)`。
- **建议**：在 `smart-parking-h5/public/` 放 favicon 或 `index.html` 里显式声明，避免噪声日志干扰问题定位。

### DEF-13 【P3】历史脏数据：0 元支付流水、重复通知、重复反馈

- **现象**：
  - 缴费管理存在 `¥0.00` 且状态「支付成功 / 已退款」的流水（如 `PAY202610281934171736`），与"0 元不生成流水"的修复目标不一致（属修复前的历史数据）；
  - 通知中心存在两份完全相同的「E2E测试通知」与「越权」；
  - 反馈处理存在两条一模一样的「投诉 / 张三 / E2E反馈」。
- **建议**：写一次性治理脚本清理 8-10 月 E2E 期间的测试数据；后续 E2E 用带时间戳的标题前缀，并在收尾步骤删除。

## 6. 结论与整改顺序

1. **立刻修（P0/P1）**：DEF-01（雪花 id 精度 + 删除/更新假成功）→ 这是"看起来成功其实没生效"的根源，且影响全模块；DEF-02（异常与 SQL 外泄）、DEF-03（并发 401 踢人）。
2. **本迭代修（P2）**：DEF-04 负价校验、DEF-05 审计 IP/耗时、DEF-06 首页状态标签、DEF-07 看板在场数、DEF-08 统计利用率。
3. **顺手修（P3）**：DEF-09 ~ DEF-13。
4. 整体质量评价：**交互层与错误兜底质量较好**（空态、二次确认、按钮显隐、路由守卫、0 元单处理均达标，2026-10-28 的 8 项前端修复全部回归通过），**问题集中在"前后端契约"与"错误信息治理"两层**：主键精度、异常映射、统计口径、并发续期。建议把 DEF-01/02/03 的三个场景补成自动化回归用例（可直接复用本次的 Puppeteer 脚本思路）。
