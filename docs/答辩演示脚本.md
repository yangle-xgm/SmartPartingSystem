## 2. 分镜脚本

### 镜头 ① 看板｜0:00–0:40

**操作**：管理端已登录，停在「概览 → 数据看板」。

**画面**：5 张卡 —— 今日入场 4、今日出场 0、当前在场 21、今日收入 ¥0、本月收入 ¥0；下方实时占用率环图 + 车流曲线。

**讲稿**：
> 这是运营看板。这些数字不是定时跑批算出来的，是每次刷新实时调 4 个微服务的接口汇总的，前端 5 秒缓存。
> 现在是 87 个车位、占用 21 个。今日收入是 0，因为种子流水都在 9 月 —— 没关系，接下来我现场跑一笔，收入、分润、流水、抬杆会一起出数。

---

### 镜头 ② 入场｜0:40–1:40

**操作**：
1. 左侧菜单「设备与智能 → 设备管理」
2. 点「模拟入场识别」
3. 摄像头选 `A区入口摄像头（CAM-A-001）`，车牌填 `湘A3P664`，置信度拉到 **95**
4. 点「发送识别指令」

**画面**：toast「联动成功：已自动入场并抬杆」，弹窗内显示「识别成功，已自动入场」+ 订单号 + 车位 `A-003`。

**讲稿**：
> 这里模拟的是一个摄像头事件。真实场景下摄像头识别出车牌后往 MQTT 发一条消息，设备服务收到后调订单服务建单、分配最近的空闲车位，再向道闸下发开闸指令。
> 置信度我设了 95。如果低于 80，会走模糊识别兜底，返回几个相似车牌让门岗确认 —— 因为现场误识别直接抬杆是要出事的。
> 车牌在库里是 AES 加密存的，我在这里看到的是解密后的视图，列表接口按权限返回。

**接一句过渡**（切到 3001 标签）：
> 同一时刻业主端会收到 —— 看，王五的首页「进行中」从 1 变成 2。

---

### 镜头 ③ 出场｜1:40–2:40

**操作**：
1. 回 3000 标签，仍在设备管理页
2. 点「出场放行」
3. 道闸选 `A区出口道闸（GATE-A-002）`，出场车牌填 `湘A8M335`
4. 点「确认放行」

**画面**：弹窗显示「已信用放行，请在 24 小时内完成支付 ¥15.00」「应付金额 ¥15.00」，道闸已开启。

**讲稿**：
> 这辆车是今天 11:45 进的场，停了 8 个多小时。计费规则是 30 分钟免费、之后 2 元一小时、单日封顶 15 元，所以算出来 15，封顶了 —— 停一整天也是 15。
> 注意这里没有拦着不让走。设计上叫「信用额度内先离场后付费」：有效额度取配置的 6 元和规则日封顶的较大者，也就是 15，所以这单直接抬杆、账单随后生成。出口堵车比欠 15 块钱麻烦得多。超出额度才会要求现场支付。
> 计费不是拍脑袋，是按车型匹配计费规则表，临停、新能源、月租、访客四套规则，都可在「计费规则」页改。

---

### 镜头 ④ 支付｜2:40–3:40

**操作**：
1. 切到 3001 标签（王五已登录）
2. 首页顶部出现「你有 1 笔订单待缴费，合计 ¥15.00」，点进去
3. 订单详情 → 点「去支付 ¥15.00」
4. 底部弹窗选「微信支付（模拟）」

**画面**：支付成功 toast；订单状态变为「已支付」；首页待缴费横幅消失。

**讲稿**：
> 业主端是独立的 Vue 应用，走的是同一个网关。支付走支付服务，落一条支付流水。
> 流水表带 `biz_type` 区分业务：1 是停车、2 是月卡。这个字段是我这轮加的 —— 之前月卡充值绕过了支付服务，账上查不到钱，属于资金链路的漏洞，现在两类业务都从同一个收银台过。
> 演示环境是模拟渠道，真实接微信要商户号和证书，这一层做了开关，生产模式会强制校验密钥、不配就拒绝启动。

---

### 镜头 ⑤ 抬杆闭环｜3:40–4:20

**操作**：回 3000，设备管理页 → 滚到「道闸指令流水」→ 点「刷新」。

**画面**：最新一条 `OPEN`，放行原因 **支付成功放行**，通道 `sandbox`／`mqtt`，回执「已回执」，耗时 **6–12 ms**。

**讲稿**：
> 钱到账之后，支付服务回调订单服务核销，核销成功再异步下发开闸。
> 这条流水记录的是「下发 → 厂商通道 → 设备回执」的完整闭环：报文、通道、有没有收到设备回执、耗时多少。
> 「放行原因」这列能区分是谁开的闸 —— 手动开闸、出口结算、支付成功放行。真出纠纷时不用翻日志，看这列就够了。
> 报文带签名，防重放；验签用的是恒定时间比较，避免计时攻击逐位猜签名。接真实厂商只要换通道实现，业务代码不动。

---

### 镜头 ⑥ 落账｜4:20–5:00

**操作**：点「概览 → 数据看板」，再点「设备与智能 → 数据统计」。

**画面**：看板今日收入 ¥0 → **¥15.00**、今日出场 0 → **1**、今日入场 4 → **5**；统计页收入曲线出现今天这个点，高峰时段显示入场最集中的小时。

**讲稿**：
> 一笔支付，四处同时变：看板收入、今日出场、流水列表、统计曲线。
> 统计服务不直查订单表 —— 微服务之间不能跨库读表，它调订单服务的内部接口取数，内部接口走网关和服务双重令牌校验，外部访问不到。这一点我专门做过边界核查，31 个内部端点全部登记在契约文档里。

---

### 镜头 ⑦ 月卡 0 元（可选，30 秒）

**操作**：设备管理 → 模拟入场识别 `湘A5R946` → 再「出场放行」同一车牌。

**画面**：入场成功；出场时应付 **¥0.00**，直接抬杆。

**讲稿**：
> 这是月卡车辆，规则 3 是 0 元一小时，出场不产生应收，也不进支付流程。
> 月卡续费在业主端走的是一个单独的收银台入口，付完由支付服务回调车辆服务续期，过期时间直接往后延。

---

### 镜头 ⑧ 越权隔离（可选，20 秒）

**操作**：H5 用 `zhangsan/user123` 登录，看「我的订单」—— 里面没有王五的单。

**讲稿**：
> 业主只能看见自己的车、自己的单、自己的流水。这个隔离不是前端过滤，是每个查询都强制带当前用户 ID 做条件，后端校验归属，换个账号或者改个参数都拿不到别人的数据。

## 4. 翻车应急

| 现象 | 原因 | 一句话兜底 |
|---|---|---|
| 登录提示验证码错误 | 图形验证码看不清 / 已过期 | 点图换一张；**已提前登录就别退出** |
| H5 页面打不开 | 3001 端口没起 | 终端 `cd smart-parking-h5 && npm run dev`，H5 是 **3001** 不是 5173 |
| 接口全 500 / 请求失败 | 网关没起，或代理指错 | 确认 8080 在跑；`/api` 代理必须写 `127.0.0.1`，写 `localhost` 在 Node 18+ 会偶发超时 |
| 入场后没分配车位 | 车位满了 | 现有 87 车位、占用 21，不会满；真满了去「车位管理」加一个 |
| 出场金额是 0 | 停车不足免费时长 | 换 `湘A8M335`（11:45 入场，稳定 15 元） |
| 出场提示「无进行中订单」 | 车牌输错，或这单已被演示过 | 跑 `docs/sql/演示后复原.sql`，重来 |
| 支付成功但流水没记录 | 看的是旧数据 | 点「刷新」；看板有 5 秒缓存 |
| 支付后没看到「支付成功放行」 | 流水里那单被刷下去了 | 流水是最近 20 条，直接从顶部找 `OPEN` + 时间最新那条 |
| 流水里某条显示「未回执」、耗时 1 秒多 | MQTT 首笔指令冷连接 | 说明这是通道建连耗时、不影响放行；下一笔就回到 10 ms 级 |
| 页面白屏 | 前端构建缓存 | `Ctrl+F5` 强刷 |
| 评委问「为什么有离线设备」 | 2 台演示设备未纳管，心跳超时标离线 | 正是设备健康监测在起作用，可以顺势讲心跳与状态机 |

## 5. 演示后复原（30 秒，演练多次必用）

```bash
cd "D:/JAVA EE/SmartPartingSystem"
docker exec -i sp-mysql mysql -uroot -p21491879 --default-character-set=utf8mb4 smart_parking \
  < docs/sql/演示后复原.sql
```

脚本做的事（幂等，可反复跑）：

1. 删掉今天创建的所有演示订单（种子 100–110 不动）
2. 删掉挂在演示订单上的支付流水与分润
3. 释放演示占用的车位
4. 删掉演示产生的通知
5. 订单 100–103 还原为「进行中、无出场、无金额」
6. 按事实重算今日统计（入场 4 / 出场 0 / 收入 0）

复原后回看板确认四个数回到 4 / 0 / 0 / 21，就可以再演一遍。
