### P1-1 ~~notify 内部令牌占位符漏 `SP_INTERNAL_TOKEN`~~ —— **复核后撤回：不是缺陷**

`smart-parking-notify/.../NotificationController.java:43`

```java
// 原写法
@Value("${smart-parking.internal-token:SmartParking-Internal-2026}")
private String internalToken;
```

首轮判定为缺陷的理由是"只读属性、不读环境变量"。**这个判断是错的**，因为漏看了 `smart-parking-notify/src/main/resources/application.yml:88`：

```yaml
smart-parking:
  internal-token: ${SP_INTERNAL_TOKEN:SmartParking-Internal-2026}
```

yml 里的值本身就是占位符，`@Value` 读 `smart-parking.internal-token` 时会连这层一起解析 —— 所以只配 `SP_INTERNAL_TOKEN` 时**拿到的就是新令牌**，广播不会 403。原报告说的"静默失败"在当前代码下不成立。

> 教训：判断占位符链路要一路查到 `application.yml`，不能只看 Java 注解。同一类误判在 payment 上曾经是真的（那处确实只读属性、yml 也没有桥接），容易形成惯性。

**虽然非缺陷，仍做了等价清理**（`Constants.DEFAULT_INTERNAL_TOKEN` + 与 `InternalApiGuardConfig` 完全一致的占位符）：默认值不再有第二份字面量，`@Value` 与守门器读同一个键，将来 yml 那行被误删也不会悄悄降级。这属于可维护性改进，**不算修复缺陷**。
