## 3. 缺陷清单

### D1【P1】预约车位：弹窗默认时段必然提交失败

- **模块**：车位预约（业主）
- **复现步骤**：`zhangsan` 登录 → 车位预约 → 点击任意绿色空闲车位 → 不修改时间，直接点「确认预约」
- **实际**：弹出两条错误提示，预约失败：
  - `车位当前不可预约或已被占用`
  - `预约开始时间不得早于当前时间`
- **原因**：`openReserve` 把开始时间截断到整分（`now.setSeconds(0,0)`），例如 11:21:42 打开弹窗，预填 `11:21:00`，已早于当前 42 秒；前端校验留了 60 秒容差放行，后端 `ParkingSpaceServiceImpl#reserve` 用 `isBefore(now())` 严格拒绝。
- **期望**：默认时段可直接提交成功（或预填时间向上取整到下一分钟）。
- **建议**：
  1. 前端预填改为「向上取整到下一分钟」，并保持 `end = start + 1h`；
  2. 前后端容差口径统一（后端允许 `now - 60s` 内，或前端不再放宽）；
  3. 参照 `smart-parking-web/src/views/reserve/index.vue#openReserve`、`#submitReserve`。

### D2【P1】业务失败提示重复弹出，且首条文案与真实原因矛盾

- **模块**：全局（登录、预约等所有写操作）
- **复现步骤**：登录页输错密码 → 观察右下角提示；或按 D1 提交预约
- **实际**：一次失败弹出 **两条** 提示。预约场景第一条是「车位当前不可预约或已被占用」（错误），第二条才是真实原因「预约开始时间不得早于当前时间」。
- **原因**：
  1. `utils/request.js` 的 `handleBusinessError` 已统一弹提示，页面 `catch` 里又 `ElMessage.error(e.message)`，形成双弹（`views/login/index.vue:211`、`views/reserve/index.vue#submitReserve` 等）；
  2. 后端把「开始时间早于当前」用了 `ErrorCode.SPACE_UNAVAILABLE(5202)`，前端 `CODE_MESSAGE[5202]=车位当前不可预约或已被占用` 覆盖了真实 message，导致第一条提示误导用户。
- **期望**：一次失败只提示一条，且文案准确。
- **建议**：
  1. 页面 `catch` 不再重复弹提示（或给请求加 `silent: true` 由页面自行提示），二者只保留一处；
  2. 后端时间参数校验改用参数类错误码（`4001`/新增 `RESERVE_TIME_INVALID`），不要复用「车位不可用」；
  3. `CODE_MESSAGE` 命中时优先展示后端 message（见 D5）。

### D3【P2】车位地图视图下筛选完全无效，统计卡也不随筛选变化

- **复现步骤**：车位管理 → 切「车位地图」→ 状态选「预约中」→ 查询
- **实际**：地图仍显示 87 个车位、统计卡仍是「总数 87 / 空闲 63 / 占用 23」，与筛选条件无关；同一筛选在「列表」视图下返回 0 条（正常）。
- **原因**：地图与统计卡取 `allSpaces`（`onMounted` 里 `loadAll()` 一次性全量），只有列表用受查询条件影响的 `tableData`（`views/parking/index.vue:274/335/349`）。
- **建议**：地图视图改用查询结果（或让 `loadAll` 带上当前筛选条件），并让统计卡跟随筛选口径，或在 UI 上明确标注「统计卡为全量口径」。

### D4【P2】软删除记录长期占用唯一索引：删除后同编号无法重建

- **复现步骤**：车位管理 → 新增 `A-0004` → 删除 → 再次新增 `A-0004`
- **实际**：`409 数据已存在，请勿重复提交`，无法重建；数据库里旧记录 `is_deleted=1` 仍然占着 `uk_space_no`。
- **影响面**：全库 8 个唯一索引均未包含 `is_deleted`——`parking_space.uk_space_no`、`vehicle.uk_plate_no`、`sys_user.uk_username`、`device.uk_device_no`、`parking_order.uk_order_no`、`payment_record.uk_pay_no` 等。业务上等价于「删掉的车位号 / 解绑的车牌 / 注销的用户名永久报废」。
- **建议**：唯一索引改为 `(业务键, is_deleted)` 组合，或把 `is_deleted` 改为「删除时间戳」参与唯一键（`deleted_at`，未删为 0），后者可支持多次删除重建；需配 Flyway 迁移脚本。

### D5【P2】前端错误码字典把后端的精确文案全部抹平

- **复现步骤**：重复新增同一车位编号 → 提示「数据已存在，请勿重复提交」；车位编号输入 42 位 → 提示「数据不合法，请检查输入」
- **实际**：后端返回的「车位编号已存在，请换一个编号」「车位编号长度不能超过 20」等具体原因被 `CODE_MESSAGE[409]`、`CODE_MESSAGE[4001]` 覆盖，用户不知道到底哪儿错了。
- **原因**：`utils/request.js` 的 `safeMessage` 优先取本地字典，字典命中即丢弃后端 message。
- **建议**：字典改为「兜底」——后端 message 非空且不含 SQL/堆栈关键字时优先展示后端文案；仅在 message 缺失或敏感时用字典兜底（`401/403/429` 这类状态语义仍可保留固定文案）。

### D6【P2】数据统计「车位利用率趋势」图例重复渲染两组

- **复现步骤**：数据统计页 → 观察右侧图表右上角
- **实际**：同时出现「● 总车位 ● 已占用」（ECharts 自带 legend）与「■ 总车位 ■ 已占用」（页面手写 `sp-legend`），视觉上像两组不同数据系列。
- **原因**：模板 `views/statistics/index.vue:44-46` 手写了图例，同时 `setOption` 里又开启了 `legend`（第 248 行）。
- **建议**：二选一，建议保留 ECharts legend（可与 tooltip/系列颜色严格对应），移除手写块；或反过来关闭 `legend.show`。

### D7【P2】业主首页「已绑定车牌」被截断且无提示

- **复现步骤**：`zhangsan` 登录 → 首页欢迎语
- **实际**：文案「已绑定 湘A\*\*\*\*7、湘A\*\*\*\*6、湘A\*\*\*\*8」，但「我的车辆」显示 4 辆，用户会以为少绑定了一辆。
- **原因**：`views/dashboard/index.vue:439` 取 `slice(0, 3)` 且未加省略说明。
- **建议**：超过 3 个时显示「湘A\*\*\*\*7 等 4 辆」或「+1」。

### D8【P3】通知角标在「标记已读」后不刷新

- **复现步骤**：通知中心 → 点某条「标记已读」/「全部已读」
- **实际**：列表内未读数立即变 0，但顶栏铃铛角标仍显示旧值，最长要等 60 秒轮询或切换路由才更新。
- **原因**：`layout/index.vue:160-176` 仅在路由变化与 60s 定时器里刷新 `unreadCount`，页面内的已读操作未通知布局层。
- **建议**：用 Pinia 存未读数，已读操作后 `store.decrement()`；或 `provide/inject` 一个 `refreshUnread()` 由 notify 页调用。

### D9【P3】车位共享开关：抽屉内切换后列表不同步

- **复现步骤**：车位详情抽屉 → 打开「共享给临停」→ 观察背后列表

- **原因**：`handleShare(current, v)` 修改的是抽屉里的 `current` 副本，未同步表格行对象（`views/parking/index.vue:476`）。
- **建议**：切换成功后按 `id` 回写 `tableData` 中对应行，或直接 `loadData()`。

### D10【P3】缴费 / 审计表格长字段折行与截断

### D11【P3】审计日志 IP 未归一化 IPv6 回环

- **复现步骤**：登录/退出后查看操作审计
- **实际**：同一台机器，部分记录是 `127.0.0.1`，部分记录是 `0:0:0:0:0:0:0:1`。
- **原因**：`WebRequestUtils#currentIp` 只对 `getRemoteAddr()` 做了回环归一化，经网关透传的 `X-Forwarded-For` 直接原样返回（`common-core/.../web/WebRequestUtils.java:34-53`）。
- **建议**：对 `X-Forwarded-For` / `X-Real-IP` 的取值也做归一化（`::1`、`0:0:0:0:0:0:0:1`、`::ffff:127.0.0.1` → `127.0.0.1`）。

### D12【P3】小区管理「车位总量 450」与车位管理「87」口径不一致

- **复现步骤**：小区管理页 vs 车位管理页
- **实际**：小区卡片 200/150/100，合计 450；车位管理实际只有 87 个车位（且全部属于 1 号小区）。
- **原因**：`community.spaces_total` 是种子数据静态值，未与实际车位表联动（`views/community/index.vue:99`）。
- **建议**：短期在页面上标注「规划车位」，长期由车位服务汇总实时数量，或建表时按真实数据校准。

### D13【P3】「收入汇总」空数据无空态提示

- **复现步骤**：数据统计页（当前区间无收入数据）
- **实际**：图表只画出 0~1 的 Y 轴与两个 0 值柱，没有「暂无数据」文案；同页另两张图是有空态处理的。
- **建议**：复用已有的 `graphic` 空态逻辑，当所有系列值均为 0 时展示「当前区间暂无收入数据」。
